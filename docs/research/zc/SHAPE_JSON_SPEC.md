# 그림 JSON 설계서 v2 — "같냐"가 아니라 "얼마나 비슷하고, 맥락까지 맞냐"

## 0. 원칙

- 그림 인식은 복사본 찾기가 아니다. **늘이거나 줄여도 같은 뼈대와 진행 순서를 가지면 같은 계열**이다.
- 시간·가격·등락%·캔들 수는 달라도 된다. 절대 숫자 하나가 그림의 정체가 되어서는 안 된다.
- 값은 언제나 **"무엇과 무엇의 관계"**로 저장한다 (예: 이번 움직임 ÷ 직전 움직임, 꼬리 ÷ 봉 길이).
- runtime이 읽는 값은 **q 시점까지 관측된 것만**. 최종 L/H, 최종 길이, ZC2, 소속 그룹은 `answer` 칸에만 두고 runtime은 읽지 않는다.

## 1. 사건 JSON (`<그룹>/events/H0010.json`)

```jsonc
{
  "event_id": "H0010",
  "side": "L",                       // L이면 그대로, H면 위아래 뒤집어 같은 언어로
  "answer": {                        // 평가 전용. runtime 금지
    "group": "G04_S01", "final_lh_bar": 133, "dual": false
  },
  "axis": {                          // 시간 늘이기/줄이기에 강한 축: 기준점 사이를 같은 칸 수로
    "anchors": ["ZC0", "A극점", "ZC1", "현재후보", "q"],
    "points_per_segment": 12,
    "segment_time_ratio": [1.0, 0.42, 0.88, 0.31]   // 구간 길이 ÷ A 구간 길이 (시간 비례만 남김)
  },
  "channels": {
    "wave": {                        // ① 현재 파동 그림
      "path":  [...48],              // (종가 - ZC1 시가) ÷ A 파동 높이, 구간마다 12점
      "high":  [...48], "low": [...48],
      "skeleton": [                  // 뼈대: 상승→눌림→재상승→꺾임 같은 순서
        {"dir": "U", "size_vs_prev": null, "time_vs_prev": null},
        {"dir": "D", "size_vs_prev": 0.38, "time_vs_prev": 0.55},
        {"dir": "U", "size_vs_prev": 1.41, "time_vs_prev": 1.20}
      ]                              // 다리를 끊는 기준 = A 파동 높이의 일정 비율 (절대값 아님)
    },
    "candle": {                      // ② 캔들 내부 형태 (구간마다 4칸 요약)
      "body_ratio":  [...16],        // 몸통 ÷ 봉 길이
      "wick_with":   [...16],        // 진행 방향 꼬리 ÷ 봉 길이
      "wick_against":[...16]         // 반대 방향 꼬리 ÷ 봉 길이

      "updates": [                   // 새 후보가 나올 때마다
        {"t_vs_A": 0.12, "depth_vs_A": 0.31, "gap_vs_prev": null},
        {"t_vs_A": 0.40, "depth_vs_A": 0.47, "gap_vs_prev": 2.3}
      ],
      "age_path": [...48]            // 후보가 나온 뒤 지난 시간 ÷ A 구간 길이
    },
    "context": {                     // ④ 앞 파동 ↔ 현재 파동 관계
      "A_vs_prev_height": 0.74,      // A 파동 높이 ÷ ZC0 전 파동 높이
      "A_vs_prev_time": 1.8,
      "prev_shape": "급락" ,         // 앞 파동 뼈대 요약 (급락 / 횡보 / 계단 …) — skeleton과 같은 규칙으로 계산
      "retrace_now": 0.62            // 지금까지 B가 A를 되돌린 비율
    },
    "macd": {                        // ⑤ MACD 다중 TF 진행 (모두 마감된 봉만)
      "h1_path":  [...48],           // 1h 히스토그램 ÷ A 구간 최대
      "m15_path": [...48],
      "m5_path":  [...48],
      "lead_lag": {"m5_turn_vs_price_ext": -0.05, "m15_turn_vs_price_ext": 0.10}  // 가격 극점 대비 전환 시점 (÷ A 시간)
    },
    "volume": {                      // ⑥ 거래량 흐름
      "path": [...48],               // 거래량 ÷ A 구간 평균
      "peak_where": [0.8, 0.1, 0.9, null],   // 구간마다 거래량 최대가 나온 위치 (0~1)
      "at_candidate": 2.7            // 후보 봉 거래량 ÷ 구간 평균

```

## 2. 그룹 JSON (`<그룹>/<그룹>.json`) — 한 파일, 한 줄짜리 정답이 아님

```jsonc
{
  "shape_id": "G04_S01",
  "n_events": 170,
  "center":   { "<채널>": [...] },          // 위치별 중앙 형태
  "band":     { "<채널>": {"p10": [...], "p90": [...], "support": [...]} },   // 허용 형태 범위
  "variants": [                              // 내부 변형 = 실제 소속 사건 중 대표(메도이드) 몇 개
    {"event_id": "H0031", "n_like": 52}, {"event_id": "H0107", "n_like": 61}, {"event_id": "H0144", "n_like": 57}
  ],
  "order":    [                              // 진행 순서 문법: 자주 나온 뼈대 순서
    {"seq": "U D U d", "share": 0.46}, {"seq": "U D U D u", "share": 0.21}
  ],
  "context":  { "A_vs_prev_height": {"p10": 0.4, "p50": 0.8, "p90": 1.6}, "prev_shape": {"급락": 0.55, "횡보": 0.30} },
  "members":  [ { "event_id": "H0013", "channels": { ... } }, ... ],    // 사건별 정보 그대로 보존 (170개 전부)
  "self_fit": { "<채널>": [...] }            // 소속 사건을 하나씩 빼고 잰 '자기 그룹과의 거리' 분포 (아래 3절)
}
```

- `members`에 170개 사건의 채널 값을 **모두** 넣는다. 평균 몇 개로 압축하지 않는다.
- `center/band/variants/order/context`는 사람이 보고 이해하기 위한 요약이고, 비교의 핵심은 `members` + `self_fit`.

## 3. 비슷함(SIMILARITY)과 맥락 맞음(CONTEXT FIT)

현재 그림(`current.json`, q까지)과 그룹 하나를 채널마다 따로 잰다.

| 채널 | 거리 | 늘이기/줄이기 처리 |
|---|---|---|
| ① 파동 | 끝난 구간은 점별 차이, **진행 중 구간은 열린 끝 DTW** (지금이 그 구간 몇 %인지 몰라도 됨) | 기준점 정렬 + DTW |
| ① 뼈대 | 다리 순서 편집거리 + 크기·시간 비율 차이 | 비율만 씀 |
| ② 캔들 | 구간 요약값 차이 | — |
| ③ 후보 흐름 | 갱신 목록 정렬 거리 (갱신 횟수가 달라도 됨) | A 시간·높이 비율 |
| ④ 앞 파동 관계 | 비율값 차이 (log) + 앞 파동 뼈대 일치 | 비율만 씀 |
| ⑤ MACD | 1h/15m/5m 경로 차이 + 선후 관계 차이 | 기준점 정렬 + DTW |
| ⑥ 거래량 | 경로 차이 + 최대 위치 차이 | 기준점 정렬 |

**거리를 '그 그룹 기준 점수'로 바꾸기 (고정 문턱 없음)**
- 그룹의 `members` 중 가장 가까운 몇 개와의 거리 = 현재 거리 d.
- 같은 방법으로 소속 사건 하나씩을 빼고 잰 거리 분포 = `self_fit`.
- 점수 = d가 `self_fit` 분포에서 어디쯤인가 (1 = 소속 사건들보다 더 가깝다, 0 = 소속 사건 누구보다 멀다).
- 이렇게 하면 넓은 그룹·좁은 그룹이 각자 자기 기준으로 재지고, 사람이 정한 숫자 문턱이 없다.

**합치기**
- CONTEXT FIT = 채널 점수 6개를 합친 값. 처음엔 같은 비중, 이후 비중은 과거 사건으로만 정한다.
- 결과는 언제나 채널별로도 같이 보여준다:

```
현재 그림 vs G04_S01
  형태 0.82 · 진행순서 0.77 · 앞파동 맥락 0.64 · MACD 0.71 · 후보진행 0.80 · 거래량 0.55  → 맥락 맞음 0.74
```

- 28개 그룹 전부와 동시에 재고, **순위**와 **"소속 사건 수준 이상으로 맞는 그룹 수"**를 같이 낸다.

## 4. 검증 3단계

1. **사건 JSON 보존 (FORM_SIMILARITY)**
   `H0010.csv → H0010.json → 다시 그림`. 픽셀 일치가 아니라:
   - 원 차트에서 뽑은 뼈대(다리 순서)와 JSON 뼈대가 같은가
   - 원 경로와 JSON 경로의 모양 상관
   - 후보 갱신 횟수·순서, MACD 전환 선후가 같은가
   → 사건마다 점수, 낮은 사건은 주소와 이유를 보고.
2. **그룹 JSON (형태 범위에 자연스럽게 들어오나)**
   소속 사건을 하나씩 빼고(LOEO) 그룹 JSON을 다시 만든 뒤, 그 사건의 점수와 28개 중 순위.
   자기 자신이 들어간 JSON으로 재면 100%가 공짜로 나오므로 금지.
3. **q-by-q 다시 흘리기**
   사건마다 q = 0부터 5분봉 하나씩. runtime은 q까지의 관측만.
   - 성공 = 최종 L/H 뒤 **+12봉 안에** 자기 그룹이 **1등**(보조: 3등 안)이 되고 그 뒤 유지
   - 같이 보고: 그때 "소속 수준 이상"인 그룹 수 (적을수록 좋음 — 28개 다 맞다고 하면 실패)
   - 더 엄격한 판: 그 사건보다 **나중에 끝난 사건은 그룹 JSON에서 뺀** 상태로 다시 측정
   - 목표 100%. 실패 사건은 숨기지 않고 주소 + 이유(두 그룹 사이 / 아직 덜 그려짐 / 맥락 다름)를 보고.
   - 미래값·사건 ID별 예외로 100%를 만들면 FAIL.

## 5. 이 저장소에서 지금 있는 것과의 관계

- `research/zc_shape_json.py` (v1): ① 파동 경로 · ⑤ MACD · ⑥ 거래량 · ③ 후보 나이를 층으로 갖고, 그룹 JSON은 center/low/high/support + 하위 그림. 사건별 정보는 그룹 JSON 안에 보존하지 않음 → v2에서 `members`·`self_fit`·뼈대·캔들·앞 파동 관계·DTW를 추가해야 함.
- `research/zc_prefix.py`: 사건 하나하나와 비교 (v2의 `members` 비교에 해당) — 4그룹 ZC2 91%, 27칸 52%.
- 한 장 그림(중앙+폭)만으로는 4그룹 75%, 27칸 44% → 사건별 정보를 버리면 떨어진다는 근거.
